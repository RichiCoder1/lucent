## Platform

adaptive

## Users

Lucent primarily serves .NET developers building cross-platform desktop applications who want a concise, typed alternative to XAML and framework-specific binding machinery.

## Product Purpose

Lucent is an experimental C#-superset language and UI framework for Avalonia. It combines normal C# logic, declarative UI syntax, compiler-managed fine-grained reactivity, CSS-authored presentation, and direct native controls. Success means proving that this can form one narrow, coherent authoring system with credible tooling and predictable runtime behavior.

## Positioning

Lucent balances three promises rather than reducing itself to one: C# without XAML, bookkeeping compiled into direct updates, and practical interoperability with native Avalonia and .NET.

## Operating Context

Developers work across `.lui`, C#, and adjacent CSS in editors such as VS Code, build through .NET and MSBuild tooling, inspect diagnostics and generated C#, and run the result as native Avalonia desktop applications. The visual system is app-first: native desktop UI establishes the grammar, and documentation derives a reading-focused expression from it.

## Capabilities and Constraints

- Lucent is currently a design and proof-of-concept project, not a stable framework or compatibility promise.
- It targets native cross-platform desktop applications through Avalonia; it does not replace Avalonia rendering.
- The language favors explicit structure, static typing, direct fine-grained updates, CSS compile-time analysis, and normal .NET interoperability.
- The identity must work across an Avalonia theme, example applications, technical documentation, and a compact application icon.
- Visual expression must not imply unsupported maturity, benchmarks, adoption, or production readiness.

## Brand Commitments

- The name is Lucent.
- The identity should read as a serious developer tool while retaining the exploratory energy of an experimental language.
- The system should be distinctive without compromising code readability, technical credibility, or everyday desktop usability.
- No existing logo, color, typeface, or visual asset is binding.

## Evidence on Hand

The repository contains the language vision and architecture, executable Counter, Todo, Package Pulse, and Workbench examples, compiled CSS and design-token support, and editor tooling. It contains no established brand assets, customer claims, benchmarks, or testimonials.

## Product Principles

1. Use normal C# until purpose-built UI syntax clearly improves the work.
2. Prefer visible structure over hidden convenience.
3. Compile away bookkeeping instead of moving it into runtime machinery.
4. Treat performance and tooling as product features.
5. Preserve native Avalonia and .NET interoperability.

## Accessibility & Inclusion

The visual system must preserve readable code and documentation, visible keyboard focus, sufficient contrast, clear control states, and native desktop interaction expectations.
