# Integrated named component feasibility probe

This bounded A0 probe combines the production compiler's named-component path with the strongest currently compatible preparation pieces. Its host projects ordinary declarations from one future-shaped `.lui.input`, runs the real .NET JSON source generator and Lucent's existing `RouteGenerator`, adds those outputs to the binding compilation, and invokes `LuiCompiler.CompileNamedComponent` for markup, state, handlers, JSON API use, and a generated route factory call.

The compiler binds and emits the same named partial component type. There is no post-lowering identity transform. That class is the actual per-mount state identity, and `AllLuiApp.Create` or `CompanionApp.Create` is an erased `ComponentRecipe` method group.

`Run-IntegratedProbe.ps1` publishes and executes two Windows NativeAOT console consumers:

- `AllLui` has only bootstrap C#; its model, JSON context, route module/record, state, method, and real `Column`/`Text` markup originate in the `.lui.input` fixture.
- `Companion` adds an optional `CompanionApp.lui.cs`. Its private `Organization` property participates in LUI binding, its generated `[State]` property initializes before LUI fields, and its single `Setup(ComponentContext)` bridge registers cleanup after LUI initialization. Runtime evidence checks two distinct mounts, state, setup, semantic output, and cleanup.

Both consumers mount twice and verify distinct named state instances plus two copies of `{"Name":"Ada"}|/home` and `real markup` in Core's semantic tree. JSON final source is regenerated by the normal .NET SDK during consumer compilation; the prepared JSON output is binding-only. The existing route generator output is captured by the host and compiled once. This avoids duplicate final JSON output while exercising the same bounded preparation distinction established by the earlier SDK-host probe.

The fixture invokes a generated route factory and observes its canonical URI. It does not mount a `NavigationSession` or `RouteOutlet`, associate a route with a component, or prove a routed application.

Run from the repository root:

```powershell
pwsh -NoProfile -File tests/Probes/ApplicationAuthoring/Integrated/Run-IntegratedProbe.ps1
```

Exact commands and exits are written to `artifacts/a0-integrated/commands-and-exits.txt`.

This fixture does not prove requirements, editor behavior, cold packaged SDK behavior, route-to-component mapping sugar, or general support-declaration parsing beyond types and delegates before one component. The host still materializes generated files, and it uses source/project references. Production generation must transport preparatory external outputs into the compiler's binding plan and compare them with final generator outputs. The fixture remains bounded A0 evidence and does not close #302.
