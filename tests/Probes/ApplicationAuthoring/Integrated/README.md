# Integrated named component feasibility probe

This bounded A0 probe combines the strongest currently compatible pieces without changing production code. Its host projects ordinary declarations from one future-shaped `.lui.input`, runs the real .NET JSON source generator and Lucent's existing `RouteGenerator`, adds those outputs to the binding compilation, and invokes the actual `LuiCompiler` for markup, state, handlers, JSON API use, and a generated route factory call.

The host then applies a deliberately narrow Roslyn transform to the real lowerer's output. It promotes the generated private state class to the named public partial component, renames the generated factory to `Create`, and rewrites its construction site. It does not reproduce state or markup lowering. The transformed class is therefore the actual per-mount state identity, and `AllLuiApp.Create` or `CompanionApp.Create` is an erased `ComponentRecipe` method group.

`Run-IntegratedProbe.ps1` publishes and executes two Windows NativeAOT console consumers:

- `AllLui` has only bootstrap C#; its model, JSON context, route module/record, state, method, and real `Column`/`Text` markup originate in the `.lui.input` fixture.
- `Companion` adds an optional `CompanionApp.lui.cs`. Its ordinary field/property merge into the same generated partial state identity, and runtime evidence reads that property from the last actual mount.

Both consumers mount twice and verify distinct named state instances plus two copies of `{"Name":"Ada"}|/home` and `real markup` in Core's semantic tree. JSON final source is regenerated by the normal .NET SDK during consumer compilation; the prepared JSON output is binding-only. The existing route generator output is captured by the host and compiled once. This avoids duplicate final JSON output while exercising the same bounded preparation distinction established by the earlier SDK-host probe.

The fixture invokes a generated route factory and observes its canonical URI. It does not mount a `NavigationSession` or `RouteOutlet`, associate a route with a component, or prove a routed application.

Run from the repository root:

```powershell
pwsh -NoProfile -File tests/Probes/ApplicationAuthoring/Integrated/Run-IntegratedProbe.ps1
```

Exact commands and exits are written to `artifacts/a0-integrated/commands-and-exits.txt`.

## Precise remaining blocker

The current LUI lowerer binds component members against its generated private helper before this prototype promotes that helper to the named class. Even when the companion syntax tree is present in the binding compilation, a LUI method cannot resolve a companion instance property. The wrapper runs `CompanionReference.lui.input` and requires the current `LUI2000` failure for `Organization`; this keeps the gap executable instead of pretending that post-lowering partial-class merging supplies cross-file semantics.

The smallest next compiler step is to make the named partial state declaration part of the lowerer's probe/binding plan before it binds LUI members, then emit that same class directly. Production generation must also transport preparatory external outputs into this binding plan and compare them with final generator outputs. A syntax transform, host-written files, and source/project references are not acceptable production architecture or package proof.

This fixture does not prove parameters, requirements, all state kinds, setup integration, source maps after transformation, editor behavior, cold packaged SDK behavior, route-to-component mapping sugar, or general support-declaration parsing. It remains A0 evidence and does not close #302.
