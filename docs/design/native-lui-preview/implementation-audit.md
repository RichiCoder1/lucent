# Native Lucent preview: implementation audit

Audit date: October 4, 2026 (America/Chicago). Source checkout: `D:\src\richicoder1\lucent`; observed HEAD `c6b6482efc9b096eb4e9f730cb89465b3e989566`. The supplied baseline was `77f1c69d`. This is a bounded static audit and an implementation handoff. No runtime changes, editor interaction, focus tests, builds, commits, or tracker changes were performed. Only this new document is owned by the audit. Recommendations below are proposed contracts, not verified behavior. Issue allocation follows the task: #231 current panel, #232 unsaved inputs and interaction, #233 onboarding/distribution, #243 future inspector. ## Main conclusion

The existing architecture supports a much clearer compact panel without replacing its coordinator: scenario selection, atomic presentation Apply, local display zoom, fresh-state rebuild, Stop, and verified diagnostic navigation already have handlers. The most urgent UX work is to make the relationship between requested controls and accepted pixels explicit, report saved-file freshness honestly, expose invalid-input feedback, and distinguish user Stop from temporary suspension. Interaction must wait for the persistent session and input ownership work in #232.

## State and lifecycle contract

Represent operation phase, accepted-frame freshness, desired running intent, and interaction eligibility separately. Existing `phase`, `stale`, `catalogStale`, controller `running`, and retained frame cover portions of this model; accepted provenance, dirty-buffer coverage, stopping completion, and input mode need additional view data. Avoid a single green “live” badge that conflates them.

| State | Frame and controls | Recovery / input |
| --- | --- | --- |
| No configuration / no accepted image | Specific setup reason; neutral empty surface, not just “No accepted image yet.” | Setup/guide/environment action. No executable input. |
| Building → discovering → rendering | Immediate stale labeling on retained pixels; show requested scenario/presentation. Apply can supersede a build atomically while running. Keep local draft fields stable. | Stop always reachable. Catalog choices are verified again before capture. No input during replacement. |
| Current #231 | “Current · saved files”; accepted-frame caption; noninteractive image. | Refresh/Apply/select rebuild and reset state. Local zoom never rebuilds. |
| Current #232 | “Current · editor snapshot” only after the frozen supported document vector was consumed and revalidated. | Input eligible only for the admitted live generation/frame and when the surface owns focus. Unsaved unsupported file types/sizes must be reported, not silently omitted. |
| Stale / build or scenario failure | Retain last accepted image with in-surface stale marker, dimming, and its old provenance. Show failure reason alongside freshness. | Choose another retained scenario or retry through a fresh build. Never interact with stale pixels. |
| Stopping → stopped | Show cleanup progress, then stopped after confirmed completion; retained image is display-only. Applied selection may be retained for Resume. | No automatic resume on show or control edits. Explicit Resume only. |
| Hidden | Suspend executable work and delivery; retain desired running intent separately. | Show starts a fresh generation only if left running. #232 cancels held input before channel loss. Do not promise retained runtime state. |
| Closed | Release panel/watchers/process ownership and selection. | A later Start follows setup again. Do not let Refresh execute without a panel. |
| Untrusted / unsupported / workspace removed | Clear input eligibility and stop owned execution; explain the actionable prerequisite. | Trust or host correction is a host flow. Never bypass the local trusted-workspace gate. |
| Cleanup blocked | Persistent explanation and retained evidence; disable rebuild/select/Apply/Resume/interaction. Keep viewing and Output available. | No “Retry” that creates a replacement owner; uncertainty must be resolved by the lifecycle owner. |
| Display delivery failure | Mark the display unavailable; do not infer the page is current merely because a frame was accepted by the host. | Host needs an explicit observable recovery path. Current five-second acknowledgment suspension is transport-only at [preview-panel.js:96](../../../extensions/lucent-lui-vscode/preview-panel.js#L96), without a corresponding product state. |

Preserve one unacknowledged frame plus one pending state, exact acknowledgments, and fresh hide/show panel sessions. The UX may expose a recovery message but must not turn an acknowledgment timeout into queued frame accumulation.

## Scenario mapping and discovery

The authored mapping already exists: `PreviewSource(project, document, component)` in [PreviewScenarioDescriptor.cs:10](../../../src/Lucent.Preview/PreviewScenarioDescriptor.cs#L10), echoed as inert labels in [PreviewMessages.cs:140](../../../src/Lucent.Preview.Protocol/PreviewMessages.cs#L140). This is enough to improve picker context now; it is not executable source navigation or runtime element inspection.

Recommended discovery order: explicitly select the development preview project and target; build and supervise catalog discovery under the existing trust rules; show authored scenario titles with IDs and origin context; suggest matching scenarios for the active source; require an explicit choice when there are several. Keep nonmatching scenarios reachable. Catalog discovery still constructs trusted author code even though it does not invoke scenario setup/root/theme callbacks ([native-preview-panel.md:27](../../../docs/plans/native-preview-panel.md#L27)). Never discover by launching the shipping app, reflection-scanning arbitrary types, or parsing recovered LSP projections.

Navigation needs a separate host check resolving authored labels against the selected project graph/workspace. A future “Open scenario source” action should send a current scenario ID; the extension resolves and verifies the file. It must not reuse a diagnostic index or let the page submit `sourceDocument` as a URI. Stale catalog entries can request rediscovery, but should be marked “from previous build.”

## #232 input, focus, and unsaved-edit contract

The preparation document already supplies the necessary ownership boundary: [preview232-preparation.md:19](../../../artifacts/preview232-preparation.md#L19), :23, :31, and :33. These are preparation recommendations, not implemented APIs.

- Keep the default viewing surface separate from explicit interaction ownership. Clicking or keyboard-activating an “Interact” affordance gives the current surface focus; new frames, refreshes, scenario changes, and error recovery do not steal it. The toolbar and presentation fields remain ordinary editor controls and never forward their keys/text to the component.
- In the interaction surface, Tab/Shift+Tab can traverse component focus only while interaction owns focus. Escape is a reserved exit: cancel held pointers/buttons/keys, clear hover, leave interaction, and return focus to the Interact opener. Do not also forward that Escape as a component event. This proposed reservation means component Escape behavior needs an explicit future policy if required; it is not existing behavior.
- Blur, hide, close, restart, source invalidation, trust loss, and delivery loss immediately revoke input eligibility and release held input. Use pointer cancel/key-up and capture cleanup; clearing hover alone is insufficient. Current image freshness is necessary but does not establish live-session readiness.
- Transform input using the actual painted image rectangle: `x = (clientX - imageLeft) * logicalWidth / paintedWidth`, with the analogous Y calculation. Display zoom/fit and letterboxing are already represented by that rectangle. Do not multiply again by render scale or `devicePixelRatio`. Ignore ordinary events outside the painted image; allow finite outside coordinates only for an owned captured drag. Normalize wheel units; keys use an explicit allowlist; committed text is a separate bounded message. Native IME/preedit parity remains outside this delivery.
- Relevant supported C#/.lui edits synchronously invalidate the entire frozen document vector; debounce only compilation. Never execute a mix of saved preparation output and unsaved compiler output. An unsupported overlay must surface an actionable failure, with no implicit Save All or partial fallback. Changes still rebuild/restart and reset fixture state; presentation Apply and Reset state must communicate that consequence.
- Keep input bound to session/generation/frame/sequence and revoke it before replacement, not after replacement pixels arrive. A live input route requires the persistent owned renderer, completion/reaping contract and bounded frame transport; the current one-shot coordinator cannot supply this solely through panel styling.

## #233 and #243 boundaries for the parent design

For #233, a first-run state should explain what is missing and offer concrete host-owned actions: select the development project, inspect the environment, and open the setup guide. Version mismatch, missing SDK/tools, missing scenario registration, untrusted workspace, and unsupported host need distinct reasons. Current in-tree tool build instructions and protocol v2 compatibility are documented at [NATIVE-PREVIEW.md:15](../../../docs/NATIVE-PREVIEW.md#L15) and :125; packaged consumer onboarding needs its own evidence. A settings/template write must be a separately named intentional setup action, never a side effect of scenario, viewport, appearance, density, scale, zoom, Refresh, or Reset controls.

For #243, reserve a mutually exclusive Inspect interaction mode only once runtime tree/hit-test and source-origin capabilities exist. Inspect clicks should select an element without activating its component handler. Tie element selection to the admitted generation/frame, clear it on rebuild, and expose unknown/unavailable origins honestly. A source reveal must use a host-verified capability. Do not show an enabled Inspector button or fabricated component properties in #231/#232; authored scenario metadata describes the scenario, not the rendered element under a pointer.

One older roadmap reference assigns inspection overlays to #232 ([native-preview-scenarios.md:103](../../../docs/plans/native-preview-scenarios.md#L103)). That conflicts with the newer preparation and the task's #243 allocation. Treat it as stale planning wording, not permission to expand #232.

## Suggested implementation order

1. #231: saved-file wording, accepted-frame provenance, validation feedback, atomic draft ownership, clear Refresh/Reset semantics, and a compact presentation/details surface. Preserve theme variables, visible focus rings, CSP, bounded snapshots, and host action validation already present.
2. #231 lifecycle follow-up: stopped editing/resume contract, stopping completion, blocked control availability, Show Output, stable DOM reconciliation, and display-delivery recovery state.

## Parent resolution — authoritative decisions

These decisions supersede conflicting recommendations above:

- Bare Escape remains application input during interaction so component menus and dialogs can be tested; do not reserve it globally. Shift+Escape releases interaction, performs held-input cleanup, and returns focus to the interaction opener. F6, Shift+F6, and workbench chords remain host-owned. This replaces the audit's proposed bare-Escape exit policy, following the parent's Opus review and VS Code documentation review.
- #232 retains the fresh rebuild/reset contract. Reset without rebuilding is declined until separate freshness and build-identity proof establishes that behavior.
- Authored source metadata already exists. Exposing safe inert origin labels in the scenario picker requires no additional owner decision; labels do not themselves grant source-navigation capabilities.
