# M2 presentation and host-input evidence

`WindowsBootstrap` sets Per-Monitor V2 before SDL initialization. `GetDpiForWindow / 96` is scale authority; SDL render output is backing size; logical Core viewport is backing divided by scale. Skia scales once into a persistent premultiplied RGBA CPU surface, then uploads it to a persistent ABGR SDL streaming texture. Vsync is required. The pair is recreated only for backing size or format changes.

`WindowsInputAdapter` maps pointer, command, and routed text/IME input. It starts SDL text input only for a projected focused text field, refreshes its candidate area after projection, and leaves it active through handled preedit; focus loss cancels composition, stops SDL, and rejects queued text. Window focus loss and host disposal cancel every tracked pointer before clearing adapter state. A temporary, host-owned comctl32 subclass observes `WM_SETTINGCHANGE` and `WM_THEMECHANGED`, chains all messages through `DefSubclassProc`, wakes SDL once, and is removed on its owning thread before window destruction (or releases its refdata at `WM_NCDESTROY`). Settings preserve prior facets for SDL Unknown or failed SPI reads, expose changed diagnostic flags as the stable stderr line `Lucent Windows settings diagnostics: <flags>`, and drain appearance authoring before the first projection; equal effective values request no frame. The Issue Browser selects authored typed light, dark, and high-contrast palettes from portable appearance, rather than applying a platform paint policy. Clipboard reads/writes are UI-thread/lifetime-bounded and report failure without clearing clipboard contents first. Cursor activation failures include SDL error text.

`tests/Lucent.Platform.Windows.Tests` covers 100/125/150/200% conversion, 3840x2160 and fractional backing, resource reuse, repeated PMv2 initialization, minimize/restore/zero-size, the restore/scale-before-backing event order, negative virtual-desktop moves, idle coalescing, separate phase timings, SDL-to-Core input/focus/capture, AltGr/dead-key/repeat bounds, geometry-only stale scenes, initial appearance draining, settings diagnostics/failure preservation, multi-pointer throwing cleanup, stale clipboard access, and cursor failures. `tools/Smoke-WindowsListener.ps1` launches only the test-owned listener host, externally observes a red marker, posts `WM_THEMECHANGED`, and requires the green marker painted only after `TakePending` consumption before ordinary close. `tools/Verify-M1.ps1` additionally derives the live Windows high-contrast/app-light state without changing it and verifies the Issue Browser's corresponding exact palette/focus pixels.
