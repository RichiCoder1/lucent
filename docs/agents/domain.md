# Domain documentation

Lucent uses a single domain context.

Before exploring or changing the product model, read:

- `CONTEXT.md`, when present, for canonical vocabulary;
- relevant decisions under `docs/adr/`.

Missing files are not errors. Create or update them lazily through domain modeling when terminology or a durable architectural decision is actually resolved.

Use glossary terms consistently in issues, plans, tests, and code. If proposed work contradicts an ADR, surface the conflict rather than silently overriding it.
