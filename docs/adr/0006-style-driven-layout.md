# Style-driven layout with retained containers

Accepted September 8, 2026. Layout containers retain their children while styles select the arrangement strategy, child placement and responsive participation. Parameterized `.lui` styles and explicit reactive condition groups make these decisions reusable without moving them into application view models. Composition conditions remain appropriate for actual content ownership changes, and interactive state such as the selected route or preferred pane extent remains behavior-owned.

The framework exposes a bounded nonvirtualizing strategy interface over its managed projection, extending the internal-only decision in ADR 0004 without replacing the engine. Strategy implementations receive measurement and placement capabilities, not mutable composition or platform objects. Per-container scratch state cannot leak between mounts; measurement requests and output geometry are validated. Virtualization continues to use a separate realization contract so an ordinary custom strategy cannot accidentally enumerate or mount an entire data source.

The initial responsive surface uses named window breakpoints, assigned from the logical window viewport before layout. The reader is explicit and its source does not depend on where it is attached. Container queries and their containment/ancestor-lookup rules are deferred. Existing assigned-container readers and finite feedback diagnostics remain compatible, but the proving consumers use window breakpoints. Conditions use reactive dependency tracking, short-circuit when inactive, and preserve existing interaction-variant precedence. Width changes inside an unchanged predicate range must not rematerialize styles or remount components.

SwiftUI's interchangeable layouts and typed child values, WinUI's separation of layout/context/container, and Compose's constrained measurement and parent-data interfaces are architectural references recorded in CREDITS.md. Lucent retains its typed style model, `.lui` source maps, owner-thread execution and NativeAOT compatibility; no framework dependency or source is imported.
