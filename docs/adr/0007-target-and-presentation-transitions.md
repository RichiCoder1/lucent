# Separate authoritative targets from animated presentation

Status: accepted by the owner, September 8, 2026; [design #142](https://github.com/RichiCoder1/lucent/issues/142). Implementation authorized September 9, after the review follow-ups and Light Notes focus continuity.

Resolve style and control targets before motion, then sample a composition-owned presentation channel for explicitly eligible properties. Application state, layout and semantics observe targets; drawing observes presented values. The accepted default cancels motion when a control-owned value is authoritative. This gives `.lui` authors automatic transitions without timers or mutable animation overrides, while retaining one typed property system and immediate input correctness.

Prefer one finite, owner-scoped motion module with native and deterministic frame adapters over either per-element effects/timers or a compositor-specific animation engine. Explicit property eligibility and a bounded paint-only first delivery make idle and disposal behavior testable. The cost is an explicit target/presentation distinction and a valid retained paint projection path; current held manual samples cannot keep their existing semantics under the production transition name. Retargeting starts from the current sample for a fresh duration, sacrificing velocity continuity to keep the initial contract deterministic and small.

See the [full design](../plans/transitions.md), [execution breakdown](../plans/transition-implementation.md) and [primary-source comparison](../plans/transition-framework-research.md). The owner accepted bounded scope, control authority, full-duration retargeting, 120 ms hover feedback with immediate press/focus/disabled/selection, color math and pair fallback, hidden/appearance policy, and coordinated experimental migration. CSS and Motion are comparative references for future refinement; no dependency or deferred feature is adopted. ADRs 0001, 0003, 0005 and 0006 remain in force.
