# Adversarial review disposition for Plans 001–002

Reviewed on 2026-08-16 by an independent fresh Pi process using
`openai-codex/gpt-5.6-terra`, with extensions, skills, context files, and write
tools disabled. The managed `pi-subagents` workflow could not start because the
installed Codex conversion extension currently invokes `node:v8.createHook`
inside Bun. The fallback reviewer read the plans, implementation, tests, domain
vocabulary, ADRs, architecture, and decisions directly.

## Accepted findings and resolutions

### 1. Runtime references were wired only for the POC (blocker)

**Accepted.** Plan 001 now includes `build/Lucent.Compiler.props`,
`build/Lucent.Compiler.targets`, runtime assembly reference wiring, and a fresh
temporary consumer build that imports the targets without a manual runtime
reference.

### 2. The documented native smoke asserted Todo while mounting Package Pulse (blocker)

**Accepted.** Plan 001 now scopes `Program.cs` and `MainWindow.cs`, requires
component-specific Todo/Package Pulse smoke cases, and makes the Package Pulse
case exercise off-thread completion plus disposal before a queued commit drains.

### 3. Computed dependency cycles could recurse indefinitely (blocker)

**Accepted.** Plan 002 now requires compile-time directed-cycle detection with
source-spanned diagnostics and tests for self and two-node cycles.

### 4. The shared Roslyn compilation was inaccessible in the plan scope (high)

**Accepted.** Plan 002 now extracts `ProjectSemanticCompilation`, includes
`NativeSymbolResolver.cs` in scope, and requires native resolution, island
binding, and editor intelligence to consume the same compilation/import context.

### 5. Keyed-row dependencies were underspecified (high)

**Accepted.** Plan 002 now defines a keyed region's dependency set as the union
of loop source, key, and all row property/content dependencies, with retained-row
and reactive-key tests.

### 6. A newly activated branch could retain default property values (high)

**Accepted.** Plan 002 now requires every branch target method to run once after
branch fields are assigned and the new root is published, plus a false-to-true
test after an independent source changed while unmounted.

### 7. Publication rollback was impossible under the original contract (high)

**Accepted.** Plan 002 now retains the old root and requires compensating
`setRoot(oldRoot)` restoration. If restoration fails, both owners are disposed,
active state is cleared, and failures are aggregated. Tests must use an adapter
that mutates before throwing.

### 8. Compiler and editor semantics could diverge (high)

**Accepted.** Plan 002 now includes `EditorIntelligence.cs` and language-server
protocol coverage, conditional traversal, and shared island scope/symbol results
for branch/shadowing contexts.

### 9. Cancellation callback failures were required but not tested (medium)

**Accepted.** Plan 001 now explicitly tests a throwing cancellation-token
callback together with throwing normal cleanups and requires one exhaustive
aggregate.

### 10. Parent disposal did not explicitly dispose the conditional region (medium)

**Accepted.** Plan 002 now requires constructor registration with
`owner.OnDispose`, idempotent region disposal, `ActiveBranch == null`, and no
content setter invocation during parent teardown.

## Optional feedback

The reviewer returned no optional suggestions. All ten findings changed the
plans because each closed an implementation ambiguity or correctness hole.

## Follow-up review

A second fresh independent review checked the revised plans and found three
remaining blocker/high issues. All were accepted:

1. **The native smoke still relied on an uncontrollable timing race.** Plan 001
   now separates deterministic post-disposal queue suppression (test dispatcher)
   from production Avalonia off-thread delivery (bounded Package Pulse native
   smoke that waits for a normal committed result before closing).
2. **The one-island-at-a-time binder interface could not produce one semantic
   model containing all islands.** Plan 002 now requires draft collection,
   `BindAll(IReadOnlyList<CSharpIslandRequest>)`, one synthetic probe tree, and a
   finalization phase.
3. **Island requests lacked expected-type context.** Plan 002 now carries the
   resolved property/content type, event delegate type, boolean condition type,
   computed-factory delegate type, role, and locals into each request, with
   explicit target-typed expression tests.

The next review found three more exactness gaps, also accepted:

1. **A local runtime hint path did not create a build edge.** Plan 001 now adds
   the runtime project through imported `ProjectReference` wiring and requires a
   consumer test from deleted/isolated runtime outputs.
2. **Deduplicated dependency IDs could not locate cycle reads.** Plan 002 now
   retains every `BoundReactiveRead(sourceId, span)` occurrence and derives the
   deduplicated dependency list separately.
3. **Mount and publication failures had been conflated.** Plan 002 now leaves the
   old branch entirely untouched on mount failure, attempts restoration only
   after publication failure, and requires exactly-once cleanup assertions.

A final fresh-process gate reviewed those corrections together with batch
binding and expected-type context. Its blocker/high-severity verdict was
`PASS`.
